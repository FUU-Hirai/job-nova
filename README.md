# JOB NOVA ローカルプロトタイプ

医療・介護・福祉の求人サイトの企画提案・画面共有・ヒアリング用です。
**架空の求人を使ったフロントエンドのデモで、実際の応募・通知は行いません。**

## 1. 起動する（Mac / Windows）

必要なもの：**Node.js 20以上**とブラウザ。Docker・GitHub・APIキー・DBは不要です。
Node.js がない場合は https://nodejs.org/ からLTS版をインストールしてください。

ZIPを展開し、ターミナルで `package.json` があるフォルダに移動します。

```bash
cd job-nova-prototype
node --version
npm run dev
```

ブラウザで **http://localhost:3000** を開いてください。
**追加のnpm依存がないため `npm install` は不要です。** `node server.mjs` でも起動できます。
起動したターミナルは開いたままにし、終了するときは `Ctrl+C` を押します。

ポート3000が使用中の場合：

```bash
# Mac / Linux
PORT=3001 npm run dev
```

```powershell
# Windows PowerShell
$env:PORT=3001
npm run dev
```

その場合は http://localhost:3001 を開きます。
HTMLファイルを直接ダブルクリックするのではなく、上記のサーバー経由で開いてください。

## 2. 操作できる画面

| 画面 | URLの末尾 | 操作 |
| --- | --- | --- |
| トップ | `#/` | 勤務地・職種検索、希望条件、求人カード |
| 求人検索 | `#/search` | 地域・職種・条件・キーワード、並び替え、0件表示 |
| 求人詳細 | `#/jobs/care-01` | 職場紹介、仕事内容、研修、一日の流れ、募集要項 |
| 応募入力 | `#/apply/care-01` | サンプル入力、必須入力・メール形式の検証 |
| 応募確認・完了 | フォームから遷移 | 入力の修正、デモ応募完了 |
| お気に入り | `#/saved` | 求人の保存・解除 |
| マイページ | `#/mypage` | デモ応募履歴、お気に入り件数 |

検索条件はURLに反映するため、ブラウザの戻る・進むでも移動できます。
スマートフォンの求人詳細では、画面下に応募ボタンを固定表示します。
一日の流れは最初の求人にのみサンプルを入れています。

## 3. ヒアリングでの見せ方（約5分）

1. ブラウザだけを画面共有し、トップの説明文と検索条件を見てもらう。
2. 「夜勤なし」や「筑前町」で探し、求人一覧→詳細を操作する。
3. 職場を選ぶうえで足りない情報、比較したい情報を聞く。
4. 応募画面の「サンプル情報を入力」を押し、確認チェック→確認→完了まで体験する。
5. マイページの応募履歴を見せ、企業側の進捗更新の運用を相談する。
6. 下記ファイルを編集・保存し、再度確認してもらう。

**画面共有だけならローカルのブラウザを見せるだけで十分です。開発環境・サーバーの公開は不要です。**
相手が自分で操作する必要がある場合は、ZIPとこのREADMEを渡してローカル起動してもらえます。
相手がNode.jsを使えない場合は、別途ホスティングによるレビュー用URLを用意する段階になります。
`localhost` のURLを送っても相手のPCからは開けません。

## 4. 修正するファイル

```text
job-nova-prototype/
  README.md
  package.json
  server.mjs           # ローカルサーバー・自動リロード
  public/
    index.html         # ヘッダー、フッター、全体のHTML
    data.js            # 求人6件・職種・地域・条件
    app.js             # 画面、検索、応募、お気に入り
    styles.css         # 色・余白・レイアウト・モバイル表示
```

| 修正したいこと | ファイル・目印 |
| --- | --- |
| 求人の給与・職場名・仕事内容 | `public/data.js` の `jobs` |
| 検索できる職種・地域・条件 | `public/data.js` の `roles` / `cities` / `conditions` |
| トップのキャッチコピー | `public/app.js` の `home()` |
| 求人詳細の構成 | `public/app.js` の `details()` |
| 応募入力項目 | `public/app.js` の `application()` と `confirmation()`、サンプル入力処理 |
| メインカラー | `public/styles.css` の `:root` にある `--green` |
| スマートフォンの見た目 | `public/styles.css` の `@media(max-width:700px)` |

`public` 内のファイルを保存すると、ブラウザが自動でリロードされます。
**フォーム入力中の自動リロードでは入力が消えるので、入力デモの前後に編集してください。**
もし自動更新されない場合はブラウザを手動で更新してください。

## 5. データの扱い・できないこと

- 求人は6件すべて架空です。施設名・給与・研修・スタッフの声もサンプルです。
- イラストはCSS・絵文字で表示します。外部画像やフォントの通信は不要です。
- お気に入りは `localStorage` に保存し、同じブラウザ・ポートで再起動後も残ります。
- 応募履歴は `sessionStorage` に求人ID・日時のみ保存します。タブのセッション終了で通常は消えます。ブラウザのセッション復元で戻る場合は、リセットを使ってください。
- フォームの氏名・メール・電話・資格・自由記述は確認中のみメモリに保持し、完了時に破棄します。実在する個人情報は入力しないでください。
- ページ下の「デモデータをリセット」で保存したお気に入りと履歴を削除できます。
- 本物の会員登録、ログイン、企業管理画面、メール・LINE通知、DB、APIは未実装です。
- 応募進捗は「デモ応募完了」のみ。企業確認中や選考中への自動更新はありません。
- 応募確認・完了画面は操作の途中でのみ表示できます。確認画面をリロードした場合は最初から入力してください。

## 6. 技術構成と本番への移行

今回は**HTML / CSS / JavaScript（ES Modules）＋Node.js標準HTTPサーバー**です。
最初のヒアリングで導線と内容をすばやく直せること、依存ライブラリの準備を省けることを優先しています。
Next.js / React / TypeScript の実装サンプルではありません。

本番化するときは以下を別途設計します。

1. Next.js / TypeScriptなどへ画面を移し、公開求人を実際のパスで配信。ハッシュ形式のデモURLを本番のSEO設計には使わない。
2. 求人検索・詳細・応募API、サーバー側入力検証、DB、応募の重複対策。
3. 認証・利用者ごとのアクセス制御・個人情報の保護・同意文言。
4. 企業による求人掲載・募集終了・応募進捗更新と通知の運用。
5. 求人情報の必要項目、メタデータ・構造化データ・サイトマップ・計測。

このデモをそのまま採用サービスとして公開する想定ではありません。
`server.mjs` は `127.0.0.1` のみで待ち受けるため、他のPCからアクセスできないローカル用です。

## 7. 動作確認ポイント

作成時にNode.jsでサーバー起動・HTTP配信と、画面生成・絞り込み・並び替え・お気に入り保存・応募確認／修正／完了・履歴のロジックを検証しています。
実ブラウザのスクリーンショットによるPC／スマートフォン表示確認は作成環境の制約で未実施です。起動後、以下を確認してください。

- PCとスマートフォン幅で横スクロールが発生しない。
- 筑前町＋看護師で1件、筑前町＋保育士で0件になる。
- 複数条件はすべて満たす求人が表示される。
- 月給順の並び替えが動く。
- お気に入りの保存・削除・リロード後の保持が動く。
- 応募の必須入力・メール形式を検証できる。
- サンプル入力→確認→修正→完了→マイページが動く。
- 実際の応募送信・個人情報の永続保存がない。

自動の再ビルドは不要です。変更後、今回直した画面と関連する導線をブラウザで確認してください。
